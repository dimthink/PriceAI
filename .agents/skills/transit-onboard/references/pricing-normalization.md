# 定价归一化

## 分离四类事实

1. 用户/站长提交口径。
2. 公开价格页展示口径。
3. 结构化价格接口原始字段。
4. PriceAI 归一化比较值。

任何不一致都保留来源、时间和原始值，不覆盖历史声明。

## New API 常见换算

设：

- `creditsPerCny`：每 1 CNY 获得的额度。
- `groupRatio`：分组倍率。
- `modelRatio`：模型倍率，缺失时按 1。

归一化有效倍率：

```text
effectiveMultiplier = groupRatio * modelRatio / creditsPerCny
```

示例：`0.04 CNY = 1 credit`，即 `creditsPerCny=25`。公开 `7x` 的有效倍率为 `7 / 25 = 0.28x`。

`1:1` 不能脱离站点额度定义直接解释为官方美元等价；需要结合页面币种和余额说明。

## 固定价格

- 图片、视频、音频等按次计费保留 `per_request` / fixed price。
- 不强行换算成 token 倍率。
- 同时保留币种、单位、请求条件和原始 payload。

## 冲突判定

- 先确认名称映射和分组是否相同。
- 再确认充值口径是否相同。
- 最后比较归一化有效倍率。
- 差异可能来自活动价、专属分组、旧截图、页面缓存或站长口径变化；没有证据时只标记待确认。

推荐后台表达：

```text
站长提交：Codex 0.045；公开接口（核验时间）：gpt-特惠 0.05。
两者存在差异，正式上架前需确认是否为活动价、专属分组或口径变化。
```

## 审计要求

- `adminNote` 保留用户原话和核验摘要。
- `verificationEvents` 记录来源、时间、端点和结果。
- `cautions` 写用户需要审核的差异，不写无证据结论。
- 前台排序和价格比较只使用明确归一化后的值。
